# SB-41 — Special requirements and technical dependencies

## Baseline and evidence status

This draft maps the acceptance criteria numbered 1–17 in [SB-24](SB-24.md), section 4, to SoW section 12. The numbers below refer to SB-24 criteria. SB-41's own completion checklist is tracked in Jira. Reconcile the mapping with [SB-38](https://el-dili.atlassian.net/browse/SB-38) when its verification plan is available.

- **Baseline requirements:** Existing SB-24 and proposal targets reproduced below for traceability. A threshold is an acceptance target.
- **Proposed requirements:** Candidate test setup and technical constraints for review. Device models, browser versions, network profiles and service configurations are recorded when selected.
- **Measured findings:** No SB-41 measurements or SB-40 pilot results were available for this draft. Device performance, service latency, avatar production effort and comprehension remain pending.
- **Unverified assumptions:** Cross-browser camera, microphone, PWA and avatar compatibility, provider availability and retention, and production capacity for the avatar lexicon require verification.

## Processing and service boundaries

- **On-device capture and landmarks:** Raw camera video stays on-device and is neither sent nor stored by the application. Capture and landmark extraction run on the device. Test permission and framing errors as well as the nominal path.
- **Optional server classification:** If selected, only required landmark sequences go to the project back end. Record when this path is enabled, its network dependency and payload/retention behavior. The selection is pending. Treat landmarks as potentially identifying.
- **External services:** Turkish STT can depend on browser or external recognition, and gloss/text conversion and TTS may use local or remote components. Document each selected provider and version, input payload, network requirements, region, logging and retention. Verify which paths send audio or text and what the user sees when a provider fails. Store credentials for any selected remote service server-side. No provider, retention guarantee or offline support is assumed.
- **Avatar production and playback:** [SB-25](../SB-25-3D-Avatar-Approach-Research.md) recommends Blender for rig/clip preparation, glTF/GLB export and Three.js for browser playback. These are candidates pending [SB-40](https://el-dili.atlassian.net/browse/SB-40) evidence. Sign recognition, motion extraction/retargeting and browser playback are distinct stages. Check rights to use the source material, rig and derived clips before use or redistribution. Record tools/versions, compatible asset format, hand and facial controls, render behavior, measured active effort and failures once available. A small pilot can establish technical feasibility under its test conditions. Full lexicon delivery and user comprehension have separate acceptance checks.
